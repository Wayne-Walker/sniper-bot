# Changelog

All notable changes to the sniper-bot (exhaustion watcher, discovery scanner,
ratio watch, macro scanners, and their Telegram/Firebase surfaces) are recorded
here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

> **Convention:** every code change in this repo must add an entry here, under
> `## [Unreleased]`, in `### Added` / `### Changed` / `### Fixed`, newest first,
> with an absolute date (YYYY-MM-DD) and the file(s) touched. See `CLAUDE.md`.

## [Unreleased]

### Added
- **sol-scanner weekly calibration review — `sol_scanner_review.py` (2026-09-06).** The scanner's `SCAN_*` gates were opening guesses with no outcome data, and nobody was going to remember to read a JSONL file. Weekly one-shot (pm2 `sol-scanner-review`, Mondays 08:00 local) that reads `reports/sol_scanner_journal.jsonl` for the last `SOL_REVIEW_DAYS` (default 7) and reports: volume + pass rate by venue; a **gate autopsy** (kills per gate — a gate killing ~everything is miscalibrated or masking the others); **near-misses** (failed exactly ONE gate, which names the threshold worth moving and by how much); the passes with their metrics; and health. Health explicitly separates "quiet market" from "scanner is dead" — it warns if the journal is >48h stale or the watchlist is near cap, and counts `rate_limited`/`error` verdicts as unjudged blind spots rather than rejections. The stats are then handed to Claude for a calibration read via `exhaustion_watch._run_claude` (subscription, `ANTHROPIC_API_KEY`/`AUTH_TOKEN` stripped — can never bill the API) and pushed with `send_telegram_private`; if Claude is unavailable the raw stats still go out, so a weekly review never silently produces nothing. `--dry` prints without pushing, `--days N` widens the window. Verified against 140 synthetic verdicts (since removed) — gate autopsy, near-miss attribution and the Claude read all produced correct output. **Not a cloud routine:** cloud agents cannot read local files, and the journal is local, gitignored, and in a repo with no commits or remote — so this runs on local pm2 like the other scheduled scanners. (`sol_scanner_review.py`, `ecosystem.config.js`)
- **Solana survivor scanner — `sol-scanner/` (2026-09-06).** New sub-bot. The TypeScript Solana sniper that this repo was originally scaffolded for (root `package.json` was `solana-sniper`, with `@solana/web3.js`/`bs58`/`ws` installed and `HELIUS_*` + `WALLET_PRIVATE_KEY` in `.env`) had its source living outside the repo in `~/Downloads/solana-sniper`, was never committed, never run, and never logged here. Source moved in under `sol-scanner/` (repo-root `package.json`, `package-lock.json`, `tsconfig.json` and `node_modules` moved down with it — nothing else at the root used them), then **rebuilt from a sniper into an alert-only scanner**. Rationale: detect-at-confirmed-commitment plus a blocking RugCheck call put the buy 1-6s after pool creation, while the bots that win that race land in the same block via Geyser/Jito — arriving late means being the snipers' exit liquidity, and every safety check makes it worse. The scanner inverts it: a detected pool is queued, not bought, and is scored only after surviving `SCAN_MATURITY_MINUTES` (default 15), which makes latency irrelevant and the safety checks free. Trading half deleted (`executor/`, `exit/`, `generate-wallet.ts`, `check-balance.ts`) — it loads no wallet and cannot trade by construction. Verified live against mainnet: all three subscriptions connect on the **free** Helius tier and a real pump.fun mint resolved and queued correctly. Alerts default **off** (`SCAN_ALERTS_ENABLED=false`) so the JSONL journal earns trust first, per the `discovery_scan.py` breakout-tier discipline. Thresholds are unvalidated opening guesses. (`sol-scanner/**`, `ecosystem.config.js`, `.env`)
- **Fixed in the process of the above (2026-09-06)** — the inherited sniper code was non-functional in four independent ways, each verified against the live APIs rather than assumed: (1) **RugCheck score direction was inverted** — the code treated `score` as 0=risky/100=safe and rejected below 70, but it is a *risk* score where low = safe (USDC and WIF both return `1`), so the gate rejected exactly the safest tokens; (2) **the scorer called `/report/summary`, which does not carry the fields it read** — `mintAuthority`/`freezeAuthority` are absent there so both authority hard-fails silently evaluated false and never fired, while `topHolders`/`totalMarketLiquidity` defaulted to 100%/$0 and rejected *every* token; now a two-stage summary-then-full call using the verified schema; (3) **mint extraction guessed fixed account indices** (`accounts[8]`/`[4]`/`[2]`) with a dead `.find()` filter that returned its own first element every time, so the quote-token skip never ran and a fee-payer wallet could be emitted as a "mint" — now read from `meta.postTokenBalances`, which names its mint explicitly; (4) **`transactionSubscribe` is an Atlas/paid-tier method** while `HELIUS_WS_URL` points at the standard endpoint, and the code never checked the subscribe response — so a rejected subscription would log "Subscribed…" and sit deaf; now `logsSubscribe` (works on every plan) with explicit confirmation/failure logging. Also fixed: keepalive `setInterval` leaked one timer per reconnect, and reconnect backoff never reset after a successful open. Rate limiting is now distinguished from rejection — the old fail-closed path meant RugCheck's rate limit silently rejected 100% of candidates. Note the pump.fun program ID in the original code was **correct** and was kept (verified on-chain); PumpSwap AMM added, since modern graduations migrate there rather than to Raydium. (`sol-scanner/src/**`)
- **USDT.D key-level alerts — hourly, level-events only (2026-09-05).** The USDT.D push was firing on *any* state change (the two most recent were `rejecting resistance → ranging` and `ranging → falling` — drift, not levels) and ran once a day at 08:15, so an actual break could sit undelivered for up to 24h. Now: (1) `should_alert()` pushes only when USDT.D is AT a key level — `broke support`/`broke resistance` (headed 🚨 *KEY LEVEL BROKEN*) or `rejecting resistance`/`bouncing off support` (headed 📍 *AT A KEY LEVEL*); drift states update the stored read and Firebase but stay silent. (2) Flap guard: a repeat of the *same* level state is suppressed for `USDTD_REALERT_H` (default 24h), while a different level state — a test escalating into a break — always fires immediately; the last-alerted state is persisted as `alert` in the store so the gate survives restarts. (3) Cron moved from `15 8 * * *` to `15 * * * *` — a break now reaches Telegram within the hour. The series still holds one point per *day* (each run replaces today's sample), so S/R is unaffected by the polling rate; cost is 24 free CoinGecko `/global` calls a day. (`usdt_dominance.py`, `ecosystem.config.js`)
- **Board-wide market regime read — `exhaustion_watch.py --review-market` (2026-09-05).** Answers "what is the market doing?" rather than "what about coin X?": labels the regime as one of bull breakout / bull trend / bull pullback / range / **bearish rally** / bear trend / bear breakdown, so a rally on broken breadth can't be mistaken for a trend. Inputs: (1) **live breadth** — `market_breadth()` sweeps daily candles for the whole `EXHAUSTION_COINS` universe concurrently (`_breadth_one()`, one candle request per coin, ~5s for 70 coins, no cache) for TRAMA trend, 50/200MA position, median 7d/30d, % green, and % of alts outperforming BTC; (2) **range breaks** — how many coins cleared/lost their 20d and 55d range (windows exclude the live bar), the check that separates a genuine board-wide break from a two-name move; (3) **USDT.D rotation** via `read_usdt_dominance()`, with its S/R, 7d/30d drift and an explicit note that it is INVERSE to crypto; (4) BTC/ETH/SOL daily structure + money flow and the ETH/BTC ratio as the alt-rotation proxy; (5) macro regime (10Y/DXY) and the bot's own market regime. Output ends with positioning, what confirms the regime, and concrete BTC + USDT.D levels that invalidate it. Shares the single-flight review lock (240s) and runs on the Claude subscription with API credentials stripped. (`exhaustion_watch.py`)
- **Spot-vs-perp basis (Bitget) — dislocation alert + breakout context (2026-08-31).** Folds a spot-vs-perp basis check into the discovery scanner (one extra Bitget spot-tickers call, no new cron): `basis = (perp-spot)/spot` for all 360+ coins on both boards, attached to every rec. (1) **Breakout/early context** — a `_basis_line` on the 🚀/⚡ messages: perp premium = leverage/FOMO-led (caution), perp discount = spot-led/hedged (healthier). (2) **Standalone ⚖️ PERP DISLOCATION alert** when |basis| ≥ `DISCOVERY_BASIS_PCT` (default 4%), liquidity + sanity filtered (both sides ≥ $2M vol, reject >40% stale/delisted-spot artifacts) — a perp discount is a liquidation-cascade / mean-reversion long (e.g. SKR ran to −16% / FLOCK −4%), a premium a fade-short. Pushes (rare, high-signal) and is journaled `source="dislocation"` for a measure-first track record. (`discovery_scan.py`)
- **USDT dominance rotation gauge — `usdt_dominance.py` (2026-08-28).** Tracks USDT.D (USDT mcap ÷ total mcap), computes its support/resistance, and reads the INVERSE crypto implication: USDT.D rejecting resistance / breaking support = 🟢 rally window for BTC+alts, bouncing support / breaking resistance = 🔴 flight to stables. Authoritative current value from CoinGecko `/global` (free), appended daily; S/R seeded once from a reconstructed backfill (USDT mcap ÷ Σ top-15 coins' mcap history, ~94% coverage, calibrated to the real current value — no free source for authoritative USDT.D history). Alerts the private chat on a state transition, publishes `intelligence/usdt_dominance`, `--show` CLI, daily pm2 cron (08:15). Folded into `--decide` (`/buy`·`/sell`) via `read_usdt_dominance()`. (`usdt_dominance.py`, `exhaustion_watch.py`, `ecosystem.config.js`)
- **Momentum-breakout previous-candle doji flag (2026-08-26).** `is_doji()` (plain per-candle doji test, no reversal-context requirement) + `ev["prev_doji"]` on `evaluate()` — flags a doji on the last completed candle so the momentum breakout can warn of indecision at the launch. (`exhaustion_watch.py`, `discovery_scan.py`)
- **Buy/sell decision support — `exhaustion_watch.py --decide <coin> <buy|sell> [userId]` (2026-08-22).** Aggregates every read into one Claude-synthesized BUY/SELL/WAIT call framed by the side: bot strategy signals (`users/{uid}/signals`), candle/doji, S/R breakout, accumulation/distribution (Chaikin A/D) on 1h+daily, RSI, funding, TRAMA, exhaustion, vs-BTC and macro. Surfaced as `/buy` `/sell` in the multi-bot. (`exhaustion_watch.py`)
- **Chart-pattern source for `--decide` (2026-08-23).** `read_chart_patterns()` reads the frontend detector's Firebase node `patterns/{coin}/{tf}` (triangles/wedges/double-bottoms with measured-move targets + accumulation/distribution zones) so `/buy`·`/sell` list active patterns and their targets in a "Signals in play" section. (`exhaustion_watch.py`)
- **Accumulation/Distribution (Chaikin A/D) + S/R breakout reads (2026-08-22).** `accdist_read()` (A/D line slope + price-vs-A/D divergence) and `sr_breakout()` (new-extreme break / bracketing levels) added to `evaluate()` and `evaluate_daily()`. (`exhaustion_watch.py`)
- **Macro conditions engine — `macro_conditions.py` (2026-08-21).** 10Y yield (^TNX) + DXY → risk-on/off regime (a "don't fight the macro" read); caches `reports/macro_conditions.json`, publishes `intelligence/macro_conditions`, daily pm2 cron, surfaced on the exhaustion alert + digest and recorded on every tracked setup. (`macro_conditions.py`, `exhaustion_watch.py`, `ecosystem.config.js`)
- **Setup outcome tracker (2026-08-13).** Every high/medium digest lean is journaled to `reports/setup_log.json` and resolved win/loss/expired (MFE/MAE in R), segmented by type via `--setups`. (`exhaustion_watch.py`)
- **Momentum-breakout, early-warning and short-breakdown tiers + outcome journal (2026-08-10 → 08-22).** Discovery scanner gained: cap-scaled 🚀 momentum breakout, ⚡ early-warning (pre-TRAMA), and 🔻 short breakdown (anti-capitulation guards, unproven/measured-first) tiers; a price-journey journal (`reports/breakout_log.json`), a weekly performance summary, and `--breakouts`/`--brief`/`--breakdown`/`--perf` CLIs (Telegram `/breakout` `/breakdown`). (`ratio_watch.py`, `exhaustion_watch.py`, `ecosystem.config.js`)
